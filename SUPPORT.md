# Support & Communication Channels

Thank you for using DEDAN Remote. This document explains where and how to seek help, report problems, and propose improvements.

---

## 1. Security Vulnerabilities

**Do NOT report security vulnerabilities through public GitHub issues.**

If you discover a security vulnerability, please report it privately:
- Via **GitHub Security Advisories**: [https://github.com/Dan12-dev-ai/dedan-remote/security/advisories](https://github.com/Dan12-dev-ai/dedan-remote/security/advisories)
- Or via direct email to maintainers: `danieldaniel122333@gmail.com`

Refer to [SECURITY.md](SECURITY.md) for full vulnerability reporting guidelines and response SLAs.

---

## 2. Bug Reports & Defects

If you experience unexpected behavior, errors, broken scrapers, or reproducible defects:
1. Search existing issues to ensure the defect has not already been reported: [GitHub Issues](https://github.com/Dan12-dev-ai/dedan-remote/issues).
2. If unresolved, submit a new report using the structured [Bug Report Template](https://github.com/Dan12-dev-ai/dedan-remote/issues/new?template=bug_report.yml).
3. Provide full logs, operating system, runtime versions (Python/Node/Docker), and minimal reproduction steps.

---

## 3. Feature Requests & Architectural Discussions

For proposals, new platform scraper suggestions, or improvements to data pipelines and ranking models:
- Submit a structured proposal via [Feature Request](https://github.com/Dan12-dev-ai/dedan-remote/issues/new?template=feature_request.yml).
- Please explain the concrete engineering motivation, affected components, and potential tradeoffs.

---

## 4. Documentation & Operational Questions

For usage questions, local deployment troubleshooting, and operational architecture:
- Review existing guides:
  - [README.md](README.md): Quick start and core workflow
  - [ARCHITECTURE.md](ARCHITECTURE.md): Technical architecture and component topology
  - [DEPLOYMENT.md](DEPLOYMENT.md): Production VM and container topology
  - [docs/API.md](docs/API.md): Complete HTTP REST reference
  - [docs/TESTING.md](docs/TESTING.md): Verification and test execution guide
- If you find discrepancies or broken instructions, submit a documentation pull request or issue.
